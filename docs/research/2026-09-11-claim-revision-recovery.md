# Claim revision output cost and recovery

Research date: 2026-09-11. Scope: primary documentation and static OSS contract review; no model calls, ingestion, or runtime writes. This note supports a design decision, not a backlog or proof of production root cause.

## Runtime boundary

The input case reports eight admitted candidates and 183 incumbents (1,464 complete pair assessments). Delta extraction limits new evidence but does not eliminate same-Unit comparison coverage. [ADR 0034](../adr/0034-unify-incremental-support-and-claim-assessment.md) requires complete coverage, conditional refinement proof and atomic lifecycle/stale guards. [ADR 0017](../adr/0017-stage-recoverable-source-unit-derivation-before-lifecycle-commit.md) already owns recoverable inference staging and forbids model calls or stage writes inside the final lifecycle transaction.

The inspected [claim revision executor](../../src/memforge/pipeline/claim_revision.py) shares challenger evidence within comparison groups and uses a workload-dependent output reserve, capped by the existing policy. At 64 pairs that reserve reaches the reported 32,768 ceiling. This is an upper bound, not evidence that every response generates that many tokens. Complete responses are assembled in memory; the implementation under evaluation must demonstrate persistence of successful subwork independently of a failed sibling.

## Findings and proposed application

1. **Reduce generated representation before changing workload.** Anthropic explicitly recommends minimizing generated and input tokens while preserving task quality. A hard output cap can cut JSON mid-response; lowering it alone is not a correctness-preserving optimization. Retain one explicit pair slot and resolved/insufficient distinction per input pair; eliminate redundant explanation/fields only where the application can reconstruct them mechanically. Keep all applicable contradiction and refinement evidence/conditions. Shorter output can reduce generation cost, but a local character comparison cannot prove latency or semantic quality. [Latency documentation](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-latency#2-optimize-prompt-and-output-length)

2. **Favor a stable, compact transport schema over a proliferation of conditional schemas.** Anthropic documents grammar compilation latency, caching, and complexity from optional properties, unions and nesting. Flattening repeated output can help, while many variant branches can trade fewer emitted fields for a more expensive grammar. Preserve a stable schema across requests and decode compact wire fields into the existing domain model; do not encode each request's Memory IDs as schema enums. Native structured output only guarantees the supported schema subset, so local semantic validation remains necessary. This is design guidance, not evidence that this incident hit a provider compilation limit: the deployed SAP/Bedrock route and historical error must establish that independently. [Structured outputs: compilation and limitations](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#how-it-works), [schema complexity](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#schema-complexity-limits)

3. **Persist validated successful inference work before atomic business commit.** LangGraph's documented pending-write pattern records each successful sibling's output even when another node fails; resume does not recompute those successful nodes. This validates the execution boundary, not a need to adopt LangGraph. Reuse MemForge's existing DerivationWork seam. Bind reusable work to exact candidate/incumbent content, evidence and support inputs, target/base/epoch, model contract and relevant policy. Validate loaded results and complete slot coverage again before reduction. A cache hit conveys computed judgment, never current lifecycle authority; all final stale and atomic guards remain. [LangGraph checkpointers: pending writes](https://docs.langchain.com/oss/python/langgraph/checkpointers#pending-writes), [ADR 0017](../adr/0017-stage-recoverable-source-unit-derivation-before-lifecycle-commit.md)

4. **Await durable storage before reporting reusable completion.** LangGraph distinguishes synchronous durability from asynchronous writes that may be lost on a crash. The same distinction matters here: awaiting a successful subwork write closes the usual sibling-failure window. A process can still fail between receiving an inference result and persisting it; this does not guarantee exactly-once model execution. Retries must safely tolerate repeated computation while preserving existing first-write/result identity rules. Additional writes cost storage and latency, so store the existing bounded semantic result and identity rather than introducing another workflow ledger. [Durability modes](https://docs.langchain.com/oss/python/langgraph/checkpointers#durability-modes)

5. **Persist safe validator details across exception boundaries.** Pydantic exposes structured error location and type via `ValidationError.errors()`; its examples also include original input. Carry an allowlisted field path and error code, not the complete error object or raw exception string. Distinguish truncation/stop reason, schema rejection, local validation and timeout across individual provider attempts and the parent logical deadline. Native schema transformations can remove constraints such as `maxLength` that are later enforced locally; therefore a local ValidationError does not by itself show a provider protocol violation. [Pydantic errors](https://docs.pydantic.dev/latest/errors/errors/), [Anthropic SDK schema transformation](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#how-sdk-transformation-works), [invalid outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#invalid-outputs)

## Bounded acceptance

Use the fixed candidate/incumbent cohort without inference: compare serialized request/schema and representative complete response budgets; prove all 1,464 pair slots remain represented. Inject one late failure and prove retry invokes only missing work. Change each causal input class and prove stale results cannot be reused or committed. Exercise SQLite and HANA store query/parameter boundaries with the same contract. Inject nested validation failure and assert safe path/type survives into the runtime event without input content. Test contradiction, directional refinement and insufficient results so compact decoding cannot turn missing proof into unrelated or independent ADD.

These checks establish correctness and avoided recomputation, not the historical provider root cause or actual throughput improvement. Those remain uncertain without per-attempt timings and output/finish information. Any live fixed-cohort execution remains a separately authorized verification. No smaller batches, narrowed destructive coverage, new lifecycle states or historical rewrites are proposed.
