# Resolve ranked search intent from validated client hints

Status: Accepted (2026-08-07)

MemForge ranked search accepts an optional Requested Retrieval Intent from an Agent Client because the client can use conversational context that is absent from the query string. The service resolves that hint through minimal deterministic validation, falls back without an LLM call when the hint is absent, and never derives intent from the query language or a semantic-versus-lexical classification. General Hybrid Retrieval and Known Item Lookup hints are honored; Relationship Exploration falls back to General Hybrid Retrieval when scoped entity linking produces no traversable entity. Deterministic Listing remains a separate operation rather than a search intent.

## Consequences

All ranked intents continue to run independent vector, content lexical, metadata lexical, and eligible relationship channels before intent-specific weighted rank fusion. Intent can alter ranking policy but cannot alter visibility, source/time facets, provenance rules, or other authorization boundaries. Agent Clients should construct a self-contained query in the user's language while preserving identifiers and domain terms; clients that omit intent retain a deterministic, provider-neutral default. Automatic Known Item Lookup requires an external identifier, code symbol, or Unicode-normalized exact match to one adapter-provided metadata field; generic metadata token participation alone remains General Hybrid Retrieval.

The MCP `search` contract requires a natural-language query and accepts `general_hybrid`, `known_item`, or `relationship` as an optional intent hint. Queryless SearchEngine and HTTP compatibility may remain behind that public contract, but deterministic current-state enumeration is exposed through `list_recent_memories`, not as a search mode. Source and time facets remain explicit caller constraints and are never inferred from intent or repository context.

Agent Clients keep Known Item queries self-contained and quote an exact title, name, or path when conversation context supplies one. For an explicitly requested Known Item Lookup, the SearchEngine preserves the complete query for vector and content retrieval and may additionally run one bounded metadata-lexical query over the first valid quoted identity. The same visibility, Source, time, memory-type, and candidate-window constraints apply to both metadata reads. Quoted text does not trigger this expansion when intent is omitted or resolved as General Hybrid Retrieval, and the service does not strip language-specific wrapper words, translate the query, or call another LLM.

The compact Agent Client response reports the requested and resolved intent, the intent source (`requested`, `deterministic`, `default`, or `fallback`), and any fallback reason. A requested Relationship Exploration with no traversable scoped entity resolves to General Hybrid Retrieval with `no_traversable_entity`. Per-result channel ranks and weighted fusion contributions remain available to evaluation and service diagnostics rather than expanding every MCP result.

The OSS contract is language-neutral and embedding-provider-neutral: it does not detect or translate query languages, and it does not claim cross-language quality for a model that lacks multilingual capability. Deterministic tests prove intent and channel behavior for Unicode queries; real cross-language quality gates run only for deployments or configurations that declare a multilingual embedding capability.

Each resolved ranked intent uses one stable fusion policy rather than language- or sentence-shape-dependent weights. The policies are ordered as vector, content BM25, metadata lexical, and relationship: General Hybrid Retrieval uses `0.45/0.30/0.15/0.10`, Known Item Lookup uses `0.15/0.25/0.50/0.10`, and Relationship Exploration uses `0.25/0.25/0.20/0.30`. Ranked search uses a default RRF damping constant of `20`. The earlier `60` default flattened top channel ranks enough that several mediocre same-language vector-plus-lexical matches could outrank a top multilingual vector-only match; `20` is the largest evaluated default that preserves that target in the first five while retaining multi-channel consensus. Deployments may still override the tuning knob, but capability claims must evaluate the configured value. A bounded deterministic sweep compares three candidate policies for each intent across two graded cases per query family, applies family-specific hard rank gates, and records aggregate MRR, NDCG@5, and Hit@5. It selects the vector-primary policy for multilingual vector recall, metadata-primary policy for exact identity, and graph-primary policy for relationship exploration. The full GoldenEval case set then remains a separate hard release gate for exact identity, metadata, graph, multilingual recall, visibility, and adapter parity; canonical targets must rank in the first five unless a stricter family gate applies.
